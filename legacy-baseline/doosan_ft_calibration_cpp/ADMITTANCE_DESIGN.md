# XJC 六维力驱动的 Doosan 导纳控制设计

本设计使用外置 XJC 传感器和已完成的 `ft20_run02_model.txt` 静态零偏/重力模型，在 Linux C++ 程序中生成位置目标，由 Doosan 位置控制器执行。它不把六维力数据直接当作关节力矩命令，也不假定 `write_data_rt()` 会让控制器内置柔顺控制使用该传感器。

## 已有条件与需要先测量的量

- 标定状态为 20/20 `COMPLETE`；5 个未参与拟合的验证姿态中，力 RMSE 约 0.11～0.15 N，力矩 RMSE 约 0.003～0.010 N·m。这是静止时的模型残差，不是运动中的噪声或响应延迟。
- 当前 `ft_acquire` 人为每 100 ms 读一次传感器；`xjc_serial.hpp` 用 Modbus RTU 请求/应答，单次请求最多可等待 500 ms。先单独记录连续 5～10 分钟的请求耗时分布、间隔、超时和掉帧率，并与机器人位姿采样时间对齐；不能从现有 100 ms 打印间隔推断传感器的最快稳定频率。
- 本次标定的安装四元数是 `q_FS=(0,0,0,1)`。实现前核对传感器轴向、力矩单位、安装零点、负载和 TCP 相对传感器原点的位置。若任一项改变，重新标定或更新变换。
- 控制器 SDK 提供普通 TCP/IP `servol()` 和实时 UDP `servol_rt()/speedl_rt()`。先用普通 `servol()` 做低速单轴原型；实时 UDP 方案应在传感器速率和 Linux 实时调度能力经实测满足后再考虑。

## 数据与坐标链

每个有效采样附带单调时钟时间戳和序号。机器人监控数据取实际**法兰**姿态而非 TCP 姿态；法兰 ZYZ 欧拉角先转四元数：

```text
q_BS = q_BF ⊗ q_FS
w_ext^S = w_raw^S - w_bias_and_gravity(q_BS)
F_ext^B = R_BS F_ext^S
τ_ext^B = R_BS τ_ext^S
```

`ft_compensator.hpp` 已实现第二式。若控制点为 TCP，且 `r_ST` 是传感器测量原点指向 TCP 的向量（传感器坐标系），则 `τ_TCP^S = τ_ext^S - r_ST × F_ext^S`。先仅用三个平移力，锁定末端方向；核对力矩符号、力臂和转动方向后再启用 6 自由度。姿态偏差的积分使用旋转矩阵/四元数的旋转向量，不直接积分 ZYZ 欧拉角。

## 共用导纳外环

平移使用米、牛顿；旋转使用弧度、牛顿米。对启用的每个自由度，离散积分虚拟质量、阻尼和弹簧模型：

```text
M_a · δẍ + D_a · δẋ + K_a · δx = w_ext
x_command = x_reference ⊕ δx
```

这里 `⊕` 是位置相加与姿态旋转组合。每周期只使用新鲜、校验通过且和机器人位姿时间相近的力数据；先做传感器死区和有限带宽低通，再积分导纳。输出要独立限制 TCP 速度、加速度、单步位移、允许工作空间、关节范围和奇异点邻域。`M/D/K`、死区和限制均为配置项，不能从静态标定结果直接推出。若力超过合理量程、数据过期、时间间隔异常、控制权丢失、SDK 拒绝命令或机器人进入非预期状态，撤销导纳运行并请求受控停止；独立急停仍由现场提供。

调参从单轴开始：用多姿态静止数据测量漂移，死区设在该漂移之上；先限小位移和低速度，再降低虚拟阻尼以增加拖动灵敏度。定点与轨迹模式先选过阻尼参数（连续模型可参考 `D_a ≥ 2√(M_a K_a)`），再用真实的通信延迟和位置跟踪误差调整。现有标定验证集的最大残差约 0.25 N 和 0.020 N·m，不能据此保证运动中也有同等精度。

| 模式 | 参考位姿 | 弹簧项 | 松手后的效果 |
| --- | --- | --- | --- |
| 1. 自由拖动 | 进入模式时记录当前位姿，之后以导纳积分值生成目标 | `K_a=0` | 阻尼使速度衰减，在新位置停住 |
| 2. 定点回位 | 进入模式时固定当前位姿 `x_home` | `K_a>0` | 位移逐渐衰减，返回 `x_home` |
| 3. 直线轨迹柔顺 | `x_ref(s)=x_start+s(x_end-x_start)`；首版锁定方向 | `K_a>0` | 位移回到 0，重新贴合直线并到达终点 |

模式 3 首版在检测到持续外力时暂停路径参数 `s`，释放后先使 `δx` 收敛到该直线上的参考点，再恢复 `s` 前进。这样“回到原轨迹”指空间路径，而不是在被推离时仍追赶原定时间表。终点到达后继续保持位置参考，直到明确退出模式。切换模式时从实际位姿初始化 `δx=0`、`δẋ=0`，先缓变参数，避免位置目标跳变。

## 控制接口与程序结构

`doosan_admittance` 可由四部分组成：串口采样线程、机器人监控线程、固定周期导纳线程、状态/日志线程。串口线程只发布带时间戳的最新样本；导纳线程不进行阻塞串口读取、文件写入或终端输出。每周期获取一致的机器人姿态与力样本，计算并发送一个受限目标，记录实际位置与命令位置的误差。

首版选普通 TCP/IP `CDRFLEx::servol(target, vel[2], acc[2], time)`，用实测能稳定维持的周期发送小幅、连续的位置目标；不在 `MoveL` 同步运动过程中叠加新的伺服命令。`servol` 与 `speedl` 不受 `change_operation_speed(50)` 限制，因此速度必须由导纳输出限幅和 API 的速度/加速度参数约束。若普通接口的延迟、抖动或跟踪误差无法满足手拖动，再评估端口 12347 的实时 UDP 接口及实时 Linux 环境。实时连接有可配置的连续丢包计数，`speedl_rt` 缺少新命令 0.1 s 会停机；不能把现有 100 ms 轮询直接移植成 1 ms 实时循环。

程序状态为 `DISCONNECTED → MONITOR_ONLY → READY → FREE/HOLD/LINE → STOPPING/FAULT`。只有模型、传感器元数据、控制权、伺服、工作模式、监控新鲜度和限位检查全部通过才进入运动状态。退出时先停止持续位置命令并向控制器请求停止，确认状态后释放控制连接；发生故障时锁定 `FAULT`，由现场检查后重新启动。

## 实施顺序与验收

1. 离线回放 `ft20_run02.csv`，验证坐标变换、死区、滤波、导纳积分和 3 种参考生成器；给每个模式添加无硬件仿真与日志回放。
2. 只读测试串口与机器人位姿的实际频率、延迟、抖动和丢包；确认传感器读数顺序与单位，并在不同姿态下验证推力/力矩符号。
3. 在仿真或虚拟控制器测试普通 `servol` 的连续跟踪、超时和停机行为，再在实体机上以单个平移轴、低速度/小工作空间测试。参数由现场逐步调节，记录每次结果。
4. 依次增加三轴自由拖动、定点回位、直线轨迹受扰；最后在确认力矩原点和安装旋转后扩展到姿态柔顺。
5. 每阶段验证松手后无持续漂移、回位无振荡、轨迹偏移和恢复有界；对断串口、旧数据、断网、控制权丢失、力突变、IK/奇异点、到限位逐项演练停机。

## 官方接口依据

- [Doosan servo motion function](https://manual.doosanrobotics.com/en/api/1.29/publish/servo-motion-function)：实时外部控制需要实时环境，普通 TCP/IP 伺服接口供非实时环境使用。
- [CDRFLEx.servol](https://manual.doosanrobotics.com/en/api/1.28/publish/cdrflex-servol)：连续跟随位置目标；不关联运行速度倍率。
- [CDRFLEx.servol_rt](https://manual.doosanrobotics.com/en/api/1.32/publish/cdrflex-servol_rt)、[CDRFLEx.speedl_rt](https://manual.doosanrobotics.com/en/api/1.29/publish/cdrflex-speedl_rt)：实时接口参数、连续命令和限制。
- [MONITORING_DATA](https://manual.doosanrobotics.com/en/api/1.29/publish/struct-monitoring_data)：实际工具和法兰位姿是不同字段。
