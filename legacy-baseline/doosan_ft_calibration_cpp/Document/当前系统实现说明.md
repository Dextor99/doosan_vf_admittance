# Doosan M0609 与 XJC 六维力传感器系统实现说明

本文记录当前 Linux C++ 工程已经实现的硬件接口、数据处理、标定结果、机械臂运动与导纳功能，并汇总开发中遇到的问题及处理情况。本文以仓库代码、采集数据和模型文件为准；未由厂家资料确认的传感器通讯细节会单独标识，不能当作已验证规格。

## 1. 系统概况

系统由 Linux 主机、Doosan M0609 六轴机械臂和安装在末端工具侧的 XJC 六维力传感器组成。主机通过 DRFL SDK 的 TCP/IP 接口读取机器人反馈并发送运动命令；传感器通过 USB 转 RS485 接口以 Modbus RTU 读取。C++ 程序在主机中完成姿态同步、静态重力与零偏补偿、外力坐标变换和导纳目标计算，再通过机器人控制器的连续位置接口 `servol()` 发送目标。

当前实现的控制范围是末端平移：单轴基坐标系 X 自由拖动、基坐标系 XYZ 自由拖动、XYZ 定点回归，以及沿基坐标系 Y 轴往返的轨迹抗扰恢复。控制期间末端方向保持不变。完整六自由度（含旋转方向）的导纳、传感器力矩驱动的姿态控制和实时 UDP 伺服控制尚未实现。

### 2.1 机器人反馈信号

程序读取 DRFL 监控数据中的：

- 六个实际关节角 J1–J6，单位为度；
- 实际 TCP 位姿 `[X,Y,Z,Rx,Ry,Rz]`，位置单位为 mm、姿态单位为度；
- 实际法兰位姿。重力补偿使用法兰方向，而不是把 TCP 姿态误当成传感器安装姿态；
- 机器人状态、安全状态、运行模式、控制权状态、连接状态和 SDK 报警回调。

运动程序申请控制权后必须观察到控制器报告 `GRANT`。若机器人处于普通 `SAFE_OFF`，程序只会在允许的安全状态下请求一次 `CONTROL_SERVO_ON`，然后等待 `STANDBY`。随后切换到 `AUTONOMOUS` 并请求 `EVENT_MOVE`；只有安全状态进入允许运动的状态（`SW_RUN` 或 `CW_RUN`）才发运动命令。示教器出现控制权转移请求时，需要现场人员确认。

本工程没有通过 DO10 或其他控制箱数字输出控制伺服，也没有使用机器人模拟量、EtherCAT、ROS 或传感器硬件触发线。程序使用的是状态与位姿监控反馈、控制权/伺服管理命令和连续 TCP 位置命令。

### 2.2 XJC 传感器数据

当前 Linux 串口代码按以下方式读取：Modbus RTU、115200 baud、8 数据位、无校验、1 停止位；站号 1、功能码 04、起始寄存器 0、读取 12 个寄存器，并校验 CRC。每两个寄存器按大端 IEEE-754 float32 解码为六个值，程序将其解释为 `Fx,Fy,Fz,Mx,My,Mz`，力单位 N、力矩单位 N·m。活动控制程序名义上每 20 ms 发起一次轮询，使用独立线程读取传感器；该间隔不构成硬实时频率保证。

**重要：上面的寄存器地址、数据编码、通道顺序、符号和单位，目前是根据本机只读通信及候选解释实现的，没有通过该准确型号的厂家通讯手册或厂家软件逐项确认。** 本地 README 已明确要求核实；厂家资料中还存在不同的寄存器地址方案。`--assume-xjc-format` 仅表示显式采用当前解释，不代表厂家已确认。未经核实轴序、符号、单位和传感器原厂标定，不应将读数用于真实力控。

## 3. 坐标系与力数据处理

标定和实时补偿的安装元数据记录为：

- 机器人姿态参考：法兰（`pose_frame=flange`）；
- 传感器到法兰的安装旋转：`q_flange_sensor=0,0,0,1`，即当前模型假设传感器轴与法兰轴对齐；
- 模型和采样元数据同时记录串口设备及候选 Modbus 参数，程序可据此检查数据与模型是否匹配。

计算链如下：

1. 将机器人反馈中的法兰 ZYZ 欧拉角转成四元数，并和传感器安装四元数合成传感器到基坐标系的方向。
2. 用法兰姿态下的重力方向计算传感器坐标系中的静态负载重力力和重力力矩。
3. 从原始六维力数据中减去模型预测的静态重力项及常数零偏，得到外部作用力/力矩估计。
4. 将补偿后的力分量旋转到机器人基坐标系，作为导纳外环输入。当前导纳程序使用三个平移力分量；补偿后的力矩暂不驱动机械臂姿态。

此方法补偿的是静止负载重力和固定偏置。机械臂运动时的负载惯性、线缆拖曳、安装偏差、温漂和通讯不同步误差不会由当前静态模型自动消除。

## 4. 六维力传感器标定

### 4.1 采集流程

工程提供手动姿态记录、只读采集和自动运动采集/标定程序。自动采集流程按确认过的计划运动到初始关节姿态，再到 20 个静态姿态；每个目标等待稳定，采集多次传感器读数并取均值。第 4、8、12、16、20 个姿态作为独立验证集，其余 15 个用于拟合。完成后程序生成原始 CSV、模型文本、补偿 CSV 和状态文件。`data/ft20_run02.csv.status` 记录了 20/20 点且状态为 `COMPLETE`。

目前工程说明中的运行示例使用初始关节角 `[90,0,90,0,90,90]`，每个姿态稳定等待 3 秒并平均 30 次读数。运动采集会控制真实机械臂，执行前须审核当前位置到初始点、初始点到全部采样点及最终返回路径。历史计划文件可能与当前流程不同，执行时应以即将使用的计划文件和程序预览为准。

### 4.2 拟合模型

模型形式为：

- 预测力 = 有符号质量 × 传感器坐标系重力 + 力零偏；
- 预测力矩 = 有符号第一力矩 × 重力 + 力矩零偏；
- 第一力矩 `h_signed = signed_mass × r_COM`。

因此模型文件中的 `hx,hy,hz` 是带符号的第一力矩，单位 kg·m；它们本身不是重心距离。重心需用 `[hx,hy,hz] / signed_mass` 计算。

`output/ft20_run02_model.txt` 当前保存的结果：

| 参数 | 结果 | 含义 |
| --- | ---: | --- |
| `signed_mass` | 0.54652165 kg | 拟合得到的有符号等效负载质量；当前结果符号为正 |
| `hx,hy,hz` | 0.00546795, 0.00307970, 0.02973903 kg·m | 传感器坐标系下的有符号第一力矩 |
| 估算重心 | 约 `[10.0, 5.6, 54.4]` mm | 由第一力矩除以有符号质量得到，相对传感器原点 |
| 力零偏 `bfx,bfy,bfz` | 0.326642, 0.094895, -5.383183 N | 传感器坐标系常量力偏置 |
| 力矩零偏 `bmx,bmy,bmz` | -0.027754, 0.059498, 0.014731 N·m | 传感器坐标系常量力矩偏置 |

本地标定设计记录中，5 个留出验证姿态的静态力 RMSE 约为 0.11–0.15 N，力矩 RMSE 约为 0.003–0.010 N·m；最大残差约 0.25 N 和 0.020 N·m。这些数字描述静止验证集，不等于运动控制下的精度、响应速度或安全等级。生成模型和 `COMPLETE` 状态也不等价于现场验收通过。

模型、数据和说明：[`ft20_run02_model.txt`](../output/ft20_run02_model.txt)、[模型元数据](../output/ft20_run02_model.txt.meta)、[20 点数据](../data/ft20_run02.csv)、[采集状态](../data/ft20_run02.csv.status)、[标定与运行 README](../README.md)。

## 5. 已实现的机械臂运动与导纳功能

### 5.1 基础关节和笛卡尔运动示例

相邻工程 `doosan_cpp` 包含与 Python 运动接口对照的 MoveJ、MoveJX 和 MoveL 演示。关节示例曾用于移动到 `[90,0,90,0,90,90]`；笛卡尔 MoveL 示例目标为 `[0,360,425,90,-180,90]`。MoveJX 在关节空间插补，不保证末端走直线；MoveL 是笛卡尔直线路径。这些是基础运动示例，与力传感器标定和导纳外环分开。

基础同步运动示例可使用全局速度覆盖 50%。连续伺服外环通过 `servol()` 直接限制目标速度和加速度，不能把全局速度滑块 50% 当作其速度控制参数。

### 5.2 导纳模式及当前参数

外环使用名义 20 ms 控制周期，按 `M·ẍ + D·ẋ + K·(x-x_ref)=F` 更新虚拟目标。力信号先经过启动零参考、死区和低通，再经速度/加速度限幅生成连续位置目标。所有模式保持当前末端姿态；作用力应施加在传感器之后的末端把手上。

| 程序 | 已实现效果 | 当前导纳参数与限制 |
| --- | --- | --- |
| `ft_admittance_x` | 基坐标系 X 单轴自由拖动；Y、Z 和姿态固定；松手后停在新位置 | M=1 kg，D=12 N·s/m，K=0，死区 0.25 N，低通 0.08 s，目标最大速度 30 mm/s、加速度 150 mm/s²；启动时设定 X 力零参考。程序内 TCP X 行程边界已禁用；X 跟踪误差超过 12 mm 仍会触发停止。默认合力软件停机阈值 200 N，可设 1–200 N |
| `ft_admittance_xyz` | 基坐标系 XYZ 自由拖动；姿态固定；松手后停在新的 XYZ 位置 | M=1 kg，D=12 N·s/m，K=0，死区 0.25 N，低通 0.08 s，XYZ 合速度 30 mm/s、合加速度 150 mm/s²；默认合力软件停机阈值 20 N。跟踪误差只打印，不作为独立停机条件 |
| `ft_admittance_xyz_return` | XYZ 定点回归；启动 TCP 作为固定参考点，施力偏离，松手后回到该点 | M=1 kg，D=12 N·s/m，K=36 N/m，死区 0.25 N，低通 0.08 s，合速度 30 mm/s、合加速度 150 mm/s²；默认合力阈值 20 N |
| `ft_admittance_y_trajectory` | 以启动 TCP 为起点，沿基坐标系 +Y 200 mm 再 -Y 200 mm，持续循环；扰动导致 XYZ 偏移，松手后回到当时的名义轨迹 | 轨迹速度 20 mm/s、加速度 50 mm/s²，每圈总路程 400 mm，周期约 20.8 s；恢复导纳 M=1 kg、D=12 N·s/m、K=36 N/m、死区 0.25 N，最大恢复速度 30 mm/s、加速度 150 mm/s²；默认合力阈值 20 N。按回车或 Ctrl+C 正常退出 |

所有程序的外力限值是软件停机阈值，不会提高传感器额定量程、改变机器人控制器安全限值或代表安全施力值。X 程序的 200 N 默认值较高，真实运行时应根据把手、传感器和现场风险选择更低且合适的阈值。程序没有人为 TCP 绝对行程边界；需依赖机器人控制器配置的工作空间/关节安全限制，并预先保证路径和线缆空间足够。

Y 轨迹中的路径参数会持续前进，即使机械臂被扰动；弹簧项把末端拉回“当前时刻对应的轨迹位置”。因此它实现的是持续重复路径跟踪和抗扰恢复，不是受扰时暂停轨迹时钟、待恢复后再从暂停相位继续。

## 6. 运行方式

在本工程目录编译：

    cd /home/hzy/Code/Doosan/doosan_ft_calibration_cpp
    make

只读监视 X 方向力，不发送机器人运动命令：

    ./build/ft_admittance_x 192.168.123.156 \
      /dev/serial/by-id/usb-FTDI_FT232R_USB_UART_BG00TFOX-if00-port0 \
      output/ft20_run02_model.txt --monitor

根据监视时手动向基坐标系各正方向轻推的读数，确定正负号后再启动。例如：

    ./build/ft_admittance_x 192.168.123.156 \
      /dev/serial/by-id/usb-FTDI_FT232R_USB_UART_BG00TFOX-if00-port0 \
      output/ft20_run02_model.txt --run 1

    ./build/ft_admittance_xyz 192.168.123.156 \
      /dev/serial/by-id/usb-FTDI_FT232R_USB_UART_BG00TFOX-if00-port0 \
      output/ft20_run02_model.txt --run 1 1 1 --force-limit-n 20

    ./build/ft_admittance_xyz_return 192.168.123.156 \
      /dev/serial/by-id/usb-FTDI_FT232R_USB_UART_BG00TFOX-if00-port0 \
      output/ft20_run02_model.txt --run 1 1 1 --force-limit-n 20

    ./build/ft_admittance_y_trajectory 192.168.123.156 \
      /dev/serial/by-id/usb-FTDI_FT232R_USB_UART_BG00TFOX-if00-port0 \
      output/ft20_run02_model.txt --run 1 1 1 --force-limit-n 20

启动运动程序后需在终端按回车确认。若控制器弹出控制权授权请求，需在示教器确认。程序在开始伺服外环前会检查初始力、模型元数据、传感器/机器人数据新鲜度、关节范围和控制状态。正常回车或 Ctrl+C 会请求慢停；通信、报警或状态异常会请求快速停止。软件停止命令不能替代独立硬件急停。

## 7. 开发中出现的问题及处理

| 现象 | 原因或诊断 | 当前处理情况 |
| --- | --- | --- |
| 只读状态显示 `access=LOSS` | 状态查询程序没有请求运动控制权，因此没有 `GRANT` 是预期结果 | 只读监视和状态查看不应为读数而抢控制权；只有准备运动时才申请控制权，并等待示教器授权 |
| 状态为 `SAFE_OFF`，程序无法运动 | `SAFE_OFF` 表示伺服未上电，并不单独说明是报警、保护停机还是空闲自动关闭；控制权也可能仍为 LOSS | 程序等待示教器批准控制权 GRANT；仅在许可的普通 SAFE_OFF 状态下发送一次伺服开启，并等待 STANDBY；不自动复位急停/保护停止，也不重复抢占控制权 |
| 伺服短暂开启后关闭 | 单次程序过早断开控制连接可能使控制权/伺服状态变化；Python 示例的全局连接生命周期不同 | 持续运行的控制程序保持 SDK 连接并在伺服准备后持续发送目标；关闭行为仍由控制器安全状态和控制权管理 |
| XJC 与机器人反馈时间差过大或数据过期 | 串口请求/应答和机器人监控回调不是硬件同步时钟；Linux 调度及串口延迟会造成时间差 | 控制程序拆分传感器读取线程和控制循环，记录到达时间，检查机器人与传感器样本新鲜度；超过 100 ms、读数错误或控制周期明显落后会退出。普通 Linux + `servol()` 仍非实时系统，偶发超时仍可能发生 |
| 小力拖动时软件超力停止 | 当时使用的合力限值较低，三轴合力达到软件阈值 | X 程序允许通过 `--force-limit-n` 设置 1–200 N，当前默认 200 N；XYZ、定点回归和 Y 轨迹默认 20 N。提高软件阈值不会提升硬件安全能力 |
| 运动到一段距离后出现 X 行程限制 | 早期程序设置了相对启动点的 X 位移边界 | 当前 X 程序已禁用软件 TCP X 行程边界；由机器人工作空间和安全限位管理。超出实际安全范围仍会由控制器处理 |
| 往返拖动时出现 TCP 跟踪误差停止 | 早期误差阈值较紧，机器人跟随动态目标时实际位姿会落后 | 当前 XYZ 自由、定点回归和轨迹程序只记录误差，不因误差单独停机；X 单轴程序仍保留 12 mm 跟踪误差停止。所有模式仍保留数据、报警、关节和控制状态检查 |
| SDK 报警 1215：`[ServoL] Limit translation acceleration is very low` | `servol()` 平移加速度上限设置过低时被控制器拒绝或报警；外环自身加速度上限与 API 跟随上限是两个不同层次 | 定点回归和 Y 轨迹的 `servol()` 跟随加速度上限已提高到 1000 mm/s²，但虚拟导纳目标仍限制为 150 mm/s²。XYZ 自由程序当前仍使用 300 mm/s²，现场若再次出现该报警应检查控制器报警详情和相应 SDK 加速度参数 |
| 报 `Robot feedback older than 100 ms` | 控制程序未在容许时间内获得新鲜的机器人监控反馈，可能与网络、SDK 线程调度或进程负载有关 | 作为输入失效保护保留，数据恢复前不继续控制。它不是传感器标定失败；普通 Ubuntu 控制环并不保证硬实时 |

## 8. 当前限制与需继续确认事项

1. **传感器通讯定义仍需厂家确认。** 应对照准确型号协议或厂家软件核实地址、float 字节顺序、轴顺序、正负号、单位及原厂滤波/标定设置。当前代码的模型数值和控制行为都依赖这套映射。
2. **安装关系假设为传感器与法兰对齐。** 若拆装后发生旋转、改变工具或改变传感器原点，应重新测量安装变换、更新元数据并重新验证补偿。
3. **当前补偿是静态重力补偿。** 加减速时的惯性力、工具接触点相对传感器原点的力矩变换、温漂和动态噪声没有完整建模。当前导纳只使用平移力，不使用力矩控制姿态。
4. **外环不是实时安全控制器。** 使用普通 TCP/IP `servol()` 和 Linux 用户态循环，不能保证固定周期；不应将其当作安全额定功能或控制器内置碰撞检测。
5. **未设置程序内 TCP 位移边界是当前明确选择。** 机器人控制器工作空间、关节限位、速度限制、工具负载和现场独立急停必须事先确认有效。关节保护范围检查不能证明笛卡尔路径无碰撞。
6. `K=0` 自由导纳不会在松手后回到起点；定点回归和轨迹恢复才使用 `K=36 N/m`。当前尚无六轴旋转导纳、全六维柔顺、运动中的碰撞识别、自动恢复报警或传感器驱动的安全停机认证。
